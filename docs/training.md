# 炉石策略模型训练

目标：理解现有卡牌的基础效果，能够使用未训练过的简单新卡，并熟练操作常规训练套牌。首轮不要求复杂 OTK。

## 训练闭环

学生持续自博弈，根据当前能力按需请教 LLM：

```text
玩家可见局面 → 学生策略与价值估计 → 是否请教
                                  ├─ 否：学生执行
                                  └─ 是：LLM 给出动作
                    ↓
             保存轨迹与教师标签
                    ↓
              更新学生，继续对局
```

初期可以频繁询问；掌握常见决策后，教师预算逐渐集中到陌生或困难的局面。整个过程使用同一套调度，不按轮数划分冷启动和自博弈阶段。

## 学生模型

保留通用语义网络：卡牌文本与数值编码、实体关系编码、公开历史编码，以及策略头和价值头。所有编码器参与训练。

输入包括己方手牌和已知牌组、双方公开场面与资源、动态效果、公开事件，以及带目标和选项描述的合法动作。卡牌效果描述和数字共同编码，避免仅靠卡牌 ID 记忆。

策略输出全部合法动作的概率；价值头估计当前玩家的最终回报。环境负责规则执行。战术评分、增益偏好和场面价值系数统一放在 Rust `hearth-bot`，用于 bot 对手和基线评测。

## 何时询问 LLM

查询分数综合考虑：

- 归一化策略熵与前两动作概率差。
- 多个学生快照的动作分歧。
- 价值估计的不确定性与决策影响。
- 卡牌组合、套牌和局面的新颖度及监督覆盖。

从低查询分数中随机抽取约 2%–5% 进行审计，检查自信错误。起步使用可记录、可调整的组合分数；积累教师和审计样本后校准查询门控。价值头只输出状态价值，逐动作收益差需要另外估计。

不把概率变尖锐直接当成学会，也不按固定日程压低调用率。遇到新卡或新对局，询问可以重新增加。

## 教师与异步调度

教师接收当前玩家可见信息、相关卡牌规则、局面 ID 和完整合法动作列表。返回首选动作、可选的可接受动作集合及简短理由。教师版本和提示词固定记录，答案按局面和动作指纹验证。

环境池并行推进对局。高价值请求暂停对应对局，等待教师后执行；普通标注请求允许学生先走，答案稍后进入监督回放。其他对局继续运行。请求队列支持去重、缓存、限流、超时和重试；失败时由学生继续，失败答案不作为标签。

持久化学生版本、查询原因、抽样概率、教师答案、延迟和 token 用量。双方使用独立教师上下文。

## 学习数据与更新

教师标签用于带权行为克隆，接受多个合理动作。规则校验用于排除无效答案；教学效果由独立对局验证。

PPO 使用终局胜负回报：胜 `+1`、负 `-1`、平局 `0`。每批采样固定学生版本，记录真实动作概率和价值。教师监督损失可以与 PPO 联合更新。

第一版采用两类并行采样：有教师介入的对局提供监督样本；完整由学生执行的对局提供 PPO 轨迹。延迟标注不改变学生轨迹，可以用于后续监督更新。旧策略轨迹、教师执行的动作不直接作为当前学生的 on-policy 样本。

从新初始化权重开始。按完整父对局划分训练、开发和测试；另留出简单卡牌及效果组合，最终测试不参与选模。训练覆盖各职业、套牌、对手和先后手，以真实套牌为主，加入适量合法扰动扩展覆盖。

## 评测

每次评测关闭教师，报告：

- 对 Rust bot、历史学生及固定对手的换边得分和置信区间。
- 各职业、套牌和对局组合的表现。
- 未见简单卡牌的使用能力。
- 固定参考局面上的查询需求，以及随机审计错误率。

同时记录每千决策的实际调用数、有效标签数、缓存命中、失败和预算限制。预期是学生独立表现提高、审计错误减少、相同难度下的教师需求下降。

## 实施顺序

1. 接入教师接口、查询门控、异步环境池和持久化请求队列。
2. 用 1,000–3,000 个真实教师标注验证请求、执行、标签回流和学生更新。
3. 同初始化、同数据划分进行有教师与无教师的受控对照，比较能力和成本。
4. 根据学习曲线扩展卡牌、套牌覆盖及训练规模。

目前 Rust bot、环境、通用 BC/PPO、并行采样和评测可用；按需 LLM 教师闭环待实现。
